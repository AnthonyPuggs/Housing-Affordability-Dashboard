# Complete UI Review - 21 May 2026

## Summary

This review assessed the local Shiny dashboard at `http://127.0.0.1:3971/` against the current modular app surface. The review covered design quality, user experience, display defects, Plotly and ggplot chart behaviour, responsive behaviour, dark/light readability, accessibility basics, and economic-chart communication quality.

No `P0` issue was found. The app's main page structure, dark theme, top-level navigation, and most desktop chart surfaces are coherent and usable. The strongest issues are a visible runtime error on the Methodology page, a broken tablet/narrow-desktop layout in the Overview score panel, and poor mobile readability for the Rental Market state chart.

## Findings

### P1 - Methodology page shows Shiny runtime errors in score diagnostic tables

**Affected surface:** Methodology page, `score_contribution_table` and `score_sensitivity_table`.

**User-visible symptom:** The page displays two error blocks: `the condition has length > 1`. These appear where the score contribution and sensitivity diagnostic tables should render.

**Reproduction:** Launch the local app, open `Methodology`.

**Evidence:**

- Browser DOM captured visible errors for `methodology-score_contribution_table` and `methodology-score_sensitivity_table`.
- R console stack:
  - `Warning: Error in if: the condition has length > 1`
  - `output$methodology-score_contribution_table`
  - `output$methodology-score_sensitivity_table`
- Screenshot: `/private/tmp/housing-ui-review-20260521/desktop2-08-methodology.png`

**Likely owner:** `R/methodology_module.R` and `R/dashboard_formatting.R`.

**Likely cause:** `R/methodology_module.R:151`, `R/methodology_module.R:153`, and `R/methodology_module.R:166` pass vectors into `fmt_index()`. `fmt_index()` at `R/dashboard_formatting.R:84` uses scalar `if (is.na(x))`, which fails for vectors.

**Recommended fix direction:** Vectorise `fmt_index()` and related formatters, or explicitly map/`vapply()` over vector inputs in the Methodology table renderers. Add a runtime-oriented test that sources the app data and evaluates the two table renderers with multi-row diagnostic data.

### P1 - Overview score panel breaks between mobile and desktop breakpoints

**Affected surface:** Overview page, National Market-Entry Affordability Score panel.

**User-visible symptom:** At `900x768`, the score panel keeps a three-column grid while the navbar has already collapsed. The component section becomes extremely tall, and text wraps vertically letter by letter. The panel height measured about `2034px` in the first score card.

**Reproduction:** Set viewport to about `900px` wide, reload the local app, open Overview.

**Evidence:**

- Screenshot: `/private/tmp/housing-ui-review-20260521/tablet-900-overview.png`
- Browser measurement: `.affordability-score-panel` used `221px 304px 277px` columns at `900px`, with `scrollWidth` exceeding visible width.
- The mobile stacking rule starts only inside `@media (max-width: 768px)`.

**Likely owner:** `app.R`.

**Likely cause:** The score panel grid is defined at `app.R:426-430`, while the single-column score layout is applied only at `app.R:700-703`. The app's navbar switches to a collapsed layout below roughly `992px`, leaving a `769-991px` breakpoint range where the score grid is too dense.

**Recommended fix direction:** Stack `.affordability-score-panel` at tablet widths, preferably at `max-width: 1024px`, or introduce a two-column tablet layout with the component metadata wrapping before it becomes narrow. The `.affordability-score-component-header` wrapping rules should apply at the same breakpoint.

### P1 - Rental Market state chart is not readable on mobile

**Affected surface:** Rental Market page, `NHHA Rental Stress by State` chart on `390x844` mobile.

**User-visible symptom:** After closing the mobile sidebar, the chart card is full width but the actual chart is cramped. The y-axis title dominates the plot area, state labels collapse together, and reliability markers/error bars compete with bar labels. The result is difficult to interpret on a phone.

**Reproduction:** Set viewport to `390x844`, open the navbar, select Rental Market, close the sidebar, inspect `NHHA Rental Stress by State`.

**Evidence:**

- Screenshot: `/private/tmp/housing-ui-review-20260521/mobile-rental-sidebar-closed.png`
- Browser measurement: chart card width about `324px`; plotly chart width about `293px`.

**Likely owner:** `R/chart_builders.R` and `R/rental_market_module.R`.

**Likely cause:** `build_rental_stress_state_plot()` at `R/chart_builders.R:181-207` uses vertical bars, a long y-axis title, error bars and reliability markers. The mobile chart container rules in `app.R:672-682` preserve height but do not adapt the chart grammar or margins for narrow screens.

**Recommended fix direction:** Use a mobile-specific horizontal bar version for state comparisons, shorten or remove the axis title on mobile, move the measure definition into the card note or hover text, and reserve visible error bars for a width where they remain legible.

### P2 - Overview Plotly click interaction logs server warnings

**Affected surface:** Overview page, clickable National Market-Entry Affordability Score trend.

**User-visible symptom:** The click interaction works in the browser, but the Shiny process logs repeated warnings each time the plotly click event is observed.

**Reproduction:** Click the Overview score trend. In this run, clicking around October 2019 changed the headline to `72.1 / 100`, and Reset to latest returned it to `22.6 / 100`.

**Evidence:**

- R console warning: `The 'plotly_click' event tied a source ID of 'overview_afford_score' is not registered. In order to obtain this event data, please add event_register(p, 'plotly_click')`.
- Relevant code reads `event_data("plotly_click", source = "overview_afford_score")` at `R/overview_module.R:255-258`.
- The chart is created with source `overview_afford_score` at `R/overview_module.R:384-388`, but no `plotly::event_register()` call is applied before returning the widget at `R/overview_module.R:390-408`.

**Likely owner:** `R/overview_module.R`.

**Recommended fix direction:** Register `plotly_click` on the score trend widget before returning it. Add a small test or source-level contract to prevent the warning from reappearing when a plot uses `event_data()`.

### P2 - Rental Market heatmap emits ggplotly matrix warnings

**Affected surface:** Rental Market page, `NHHA Rental Stress Trends (Over Time)` heatmap.

**User-visible symptom:** No obvious blank chart was seen, but the R process logs matrix-length warnings while rendering the heatmap. This creates risk that hover text, fill domains, or tile text are misaligned.

**Reproduction:** Open Rental Market in the local app.

**Evidence:**

- R console warnings:
  - `data length [182] is not a sub-multiple or multiple of the number of rows [9]`
  - `g$hovertext ... data length [182] is not a sub-multiple or multiple of the number of rows [9]`
- The chart builder maps both tile fill and hover text in `R/chart_builders.R:213-217`.

**Likely owner:** `R/chart_builders.R` and `R/rental_market_module.R`.

**Recommended fix direction:** Inspect the rectangularity of the heatmap input by `survey_year` and `geography`, and check whether ggplotly conversion is receiving a regular tile grid. If not, complete the grid before plotting or simplify the text mapping so hover text aligns one-to-one with tiles.

### P2 - Shared Plotly helper ignores its `hovermode` argument

**Affected surface:** Shared Plotly rendering helper.

**User-visible symptom:** Chart hover behaviour cannot be controlled through `dashboard_ggplotly(..., hovermode = ...)`, even though the helper exposes that argument.

**Evidence:**

- `dashboard_ggplotly()` forwards `hovermode` to `plotly_layout()` at `R/plotly_helpers.R:3-6`.
- `plotly_layout()` accepts `hovermode` at `R/dashboard_theme.R:29`, but never adds it to the `plotly::layout()` arguments at `R/dashboard_theme.R:40-50`.
- Plotly layout guidance expects hover mode to be set explicitly in chart layout when a coordinated hover experience is desired.

**Likely owner:** `R/dashboard_theme.R`.

**Recommended fix direction:** Add `hovermode = hovermode` to `layout_args`, then decide chart by chart whether `x`, `x unified`, or `closest` is best. This should be tested at least on line charts, faceted charts, bar charts, and heatmaps.

### P3 - Browser console contains repeated third-party datepicker deprecation warnings

**Affected surface:** App-wide browser console.

**User-visible symptom:** No visual user-facing issue observed. The console contains repeated warnings from `bootstrap-datepicker.min.js` about deprecated language codes and filename conventions.

**Evidence:** Browser console warnings repeated after reloads and navigation.

**Likely owner:** Dependency surface via Shiny/bslib date inputs.

**Recommended fix direction:** Treat as low priority unless CI/browser QA begins treating warnings as failures. If warnings become noisy, check whether a Shiny/bslib dependency update or datepicker locale configuration removes them.

## Page-by-Page Notes

### Overview

Desktop at `1440x900` is visually strong. The hierarchy is clear, the score caveats are prominent, and the main KPI cards are readable in dark mode. The score trend click and reset interaction worked. The main defect is the tablet breakpoint failure in the score panel.

The median-price chart and affordability-index chart render, but they sit below the first viewport. That is acceptable for a dashboard, though the page is long and should remain careful about first-screen density.

### Price Trends

Desktop Dwelling Price Index and Rent CPI tabs render without visible errors. The `Units` dwelling type and `Annual change (%)` Rent CPI controls updated the plotted outputs. The chart notes correctly distinguish price indexes from affordability and burden measures.

### Affordability

The Indices tab renders two Plotly charts and the sidebar controls are responsive on desktop. The Calculator tab updated outputs after changing the dwelling price to `900000`; observed outputs included `$4,317`, `43.2%`, and `10.0 yrs`. Housing Stress and Cost Burden tabs rendered without visible Shiny errors.

The page is dense but consistent with a technical policy dashboard. Slider tick labels are crowded in sidebars, especially for date ranges and numeric controls, but this is secondary to the larger responsive defects.

### Geographic Affordability

The four SIH-aligned charts render on desktop without visible Shiny errors. The two-column chart layout is efficient for desktop scanning. Mobile was not deeply tested beyond the global responsive pass, but the chart set should be checked after fixing the Rental Market mobile chart pattern because it uses similarly information-dense SIH plots.

### Market Context

Mortgage rates, labour-market spare capacity, and population-demand charts render cleanly on desktop. The page uses the available width well and has a clearer chart hierarchy than the most dense pages.

### Housing Supply

Building approvals and CPI new dwelling purchase charts render without visible Shiny errors. The default state/type/sector filtering is understandable, and the supply page benefits from having fewer simultaneous concepts than the Affordability page.

### Rental Market

Desktop renders all four charts. The mobile sidebar can be closed and the chart card becomes visible, but the first state chart is not readable at phone width. This page should receive the next mobile-specific chart treatment because it is explicitly part of the release smoke checklist.

### Methodology

The page content structure is strong: it separates official SIH/NHHA measures, stylised market-entry indexes, the National Housing Affordability Score, caveats, and release provenance. The download button is visible. However, the two score diagnostics tables currently fail at runtime, making this the clearest functional bug in the rendered UI.

## Interaction Checks

- Overview score trend click: worked, but logged unregistered Plotly click warnings.
- Overview Reset to latest: worked after score selection.
- Price Trends dwelling type: `Units` selected and chart remained rendered.
- Price Trends Rent CPI data type: `Annual change (%)` selected and chart remained rendered.
- Affordability Calculator: changing dwelling price updated repayment, ratio and years-to-save outputs.
- Affordability nested tabs: Calculator, Housing Stress and Cost Burden rendered without visible errors.
- Mobile navbar: opened and collapsed after selecting Rental Market.
- Mobile Rental Market sidebar: can be closed, but the resulting first chart is cramped and hard to read.

## Recommended Fix Order

1. Fix the Methodology table renderers or vectorise `fmt_index()`, then add a runtime test for score diagnostics tables.
2. Fix the Overview score panel tablet breakpoint by aligning the score-panel layout breakpoint with the navbar/tablet range.
3. Add a mobile-specific Rental Market state chart treatment, preferably a horizontal bar chart with shorter axis labelling.
4. Register the Overview Plotly click event and add a source-level guard for event registrations.
5. Investigate the Rental Market heatmap ggplotly matrix warnings and verify hover text alignment.
6. Wire `hovermode` through the shared Plotly helper.
7. Decide whether third-party datepicker console warnings should be tolerated or suppressed through dependency/configuration updates.
